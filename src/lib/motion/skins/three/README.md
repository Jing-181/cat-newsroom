# 3D 玩偶皮肤

把同一份二维关节点画成一个有体积、有光照的小人。契约见 `../CONTRACT.md`，
完整姿势数据来自 `../../core.js`。

实物入口：`/lib/motion/skins/three/demo.html`（深底三动作并排，带自检开关），
或统一对照页 `/preview/skins.html`（三种画法横着比）。

## 为什么没有 Three.js

这个目录叫 three，但里面没有 Three.js，也没有任何新依赖。原因不是省事：

- 形状只有两种——胶囊和球。真三维网格每帧要么重建缓冲、要么发几十个 draw call；
  解析求交把整副骨架压成**每帧一次 drawArrays**（三个部位合一，实测 3 实例 3 次）。
- 打包体积：`three` 的 ES 模块包压缩后 150 KB 上下，而这里整套渲染 5 KB。
- 上下文配额：审查页一屏九个实例，Three.js 的 WebGLRenderer 是每实例一个上下文，
  页面上挂四五个就要撞浏览器上限。这里所有实例共用一个。

如果将来真需要骨骼网格、贴图、后处理，再换 Three.js 是对的；现在换是给一个
二十根胶囊的场景付一整套引擎的钱。

## 用法

```js
import { createSkin } from "./skins/three/three-skin.js";
const skin = createSkin(svg, { proportions });   // 拿到的 svg 就是线条稿用的那个
skin.resize(clip.viewBox);                        // 不调也行，构造时会读 svg 上的 viewBox
skin.paint(pose);
skin.paintProp(clip.prop, pose);
skin.destroy();
```

`paint` 只写一块预分配的 `Float32Array`，真正的绘制排在微任务里，
所以同一轮的 `paint` + `paintProp` 合成一帧（静帧只调一次也不会丢器械）。

## 三个技术判断

**1. 方案 C：只做「3D 渲染质感」，不反推三维姿态。**
数据源是二维投影，硬解三维关节角必然穿帮（膝盖会跑到腿外、肘会穿进躯干）。
这里给每个部位补一条固定厚度：x、y 直接用关节点，z 按身体部位给常量。
于是它是一副厚度恒定的浮雕骨架，但每段肢体都是真圆柱、有真法线、有真的前后遮挡。
代价是它转不了角度——换机位就会露馅。侧视动作里不会。

**2. 表面在片元里解析求交，顶点只当包围盒。**
一段肢体的屏幕包围盒 + 一次「投到骨轴上、落在半径内才算命中」的求交，
得到的轮廓是精确的（放大不出多边形棱角），法线也是解析的，
二十个部位合成一个顶点缓冲、一次绘制。

**3. 所有实例共用一个 WebGL 上下文。**
离屏画布轮流画，画完 `drawImage` 拷进各自的 2D canvas。上下文数量恒为 1，
销毁最后一个实例时用 `WEBGL_lose_context` 主动还回去。

## 每帧开销

| 项 | 量 |
| --- | --- |
| 几何段（`layout` + `layoutProp`，纯 CPU） | ~1.1 µs / 次 |
| 顶点上传 | 7.3 KB / 帧 / 实例（缓冲按上限一次分配，之后整块覆盖） |
| GL 调用 | 1 次 `bufferSubData` + 1 次 `drawArrays`（132 顶点 / 44 三角形） |
| 合成 | 1 次 `drawImage` |
| 上下文 | 全页 1 个 |

## 文件

| 文件 | 职责 |
| --- | --- |
| `three-skin.js` | 契约入口：挂 canvas、量尺寸、排帧、降级 |
| `three-doll.js` | 姿势 → 部位摆放（零 DOM，可在 node 里直接跑） |
| `three-shader.js` | 顶点/片元着色器与程序编译 |
| `three-gl.js` | 共享上下文、缓冲、投影、合成 |
| `demo.html` | 自检页（`?probe=1` 跑性能与上下文检查） |

## 已知妥协

- **厚度是假的。** 三维姿态不可用，只保证侧视读得对。仰卧（bench）时腿不再朝地面支撑，
  这里沿身体轴摊平——`core.js` 那一层没有「腿部支撑约束」，躺姿动作都是近似。
- **只有一条手臂的数据。** 远侧手臂照抄近侧关节角，靠 x/z 错开几个单位让它能被看见。
  分腿蹲这类真的分左右腿的动作，远侧腿用的是 `kneeFar` / `ankleFar`，是准的。
- **杠铃片朝镜头。** 真实侧视里杠片是边缘朝外的细条，屏幕上什么都看不见；
  这里跟线条稿一样选择「读得出来」而不是「投影正确」。
- **接缝是假的。** 沿肢体等距的暗线是着色器画的模具线，用来提示圆柱曲率。
- **降级画的是线条稿。** WebGL 不可用时整体退回 `../line/line-skin.js`：
  同一份关节点，姿势仍然正确，只是换了个画法，不会白屏。
