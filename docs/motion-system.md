# 动作动画系统

> ⚠️ **2026-11-07 作废。** SVG 线条小人方案暂停，本文档里的画法规范（线宽、尺寸档、头身比、视角、皮肤）全部不再执行。
> 只保留两块，见 docs/motion-keep.md：人体结构、运动轨迹。来龙去脉见 docs/motion-archive-2026-11-07.md。


> 代码正本：`src/lib/motion/`。这篇文档只写规则和契约，不复述实现。
> 适用：训练页的小人、以后任何「会动的线条图形」。界面反馈（hover、弹窗淡入）不在这套里，见文末边界。

## 一句话

**动作是数据，画法是皮肤，时间是播放器。** 三者之间只通过骨架的关节点说话，谁也不认谁。

## 分层

| 层 | 文件 | 负责 | 禁止 |
| --- | --- | --- | --- |
| 数学 | `motion/core.js` | 缓动、骨架比例、两骨 IK、剪辑采样 | 不碰 DOM，不认颜色/粗细/class，不认项目 |
| 内容 | `motion/clips.js` | 每个动作的关键姿势与节奏、动作名归类 | 不写颜色、不写 px、不写 class |
| 时间 | `motion/player.js` | rAF、限速、页面不可见暂停、减少动态 | 不知道画的是什么 |
| 画法 | `motion/svg-skin.js` | 笔触、粗细、透明度、层级、class | 不读时间，不算关节 |
| 组装 | `motion/index.js` | 把上面四层接起来，给一个 cleanup | 不塞业务逻辑 |

这个切法的用处很直接：

- 改节奏 → 只动 `clips.js` 里的秒数
- 改幅度 → 只动 `clips.js` 里的角度
- 改画风 → 只动 `svg-skin.js` 和 CSS
- 换项目 → `core.js` + `player.js` 原样带走，重写 `clips.js` 和皮肤

## 契约

### 姿势参数

一副骨架由这几个量决定。所有角度单位是度，长度单位是「身体单位」（不是 px，viewBox 决定它最终多大）。

| 字段 | 默认 | 含义 | 常用范围 |
| --- | --- | --- | --- |
| `hipHeight` | 50 | 髋离地高度 | 28–50 |
| `hipShift` | 0 | 髋相对踝的前后位移，负为往后 | -12–8 |
| `lean` | 0 | 躯干前倾角 | 0–75 |
| `armSwing` | 0 | 上臂从「自然下垂」量起的前摆角，180 为举过头顶 | 0–180 |
| `elbow` | 0 | 屈肘角，0 为直臂，160 约等于手到肩 | 0–160 |
| `rootTilt` | 0 | 整体绕踝旋转，俯卧撑/卧推这类趴着的动作用 | 0–90 |

腿用 IK 解（脚踩在地上、髋在动，这是约束）；手臂用正向解算（手没有被钉住，肘弯多少手就到哪里）。这是这套骨架最重要的一条取舍，别改回去。

### 剪辑

```js
{
  id: "squat",
  label: "深蹲",
  duration: 3.8,        // 一次完整重复的秒数
  loop: true,           // 缺省 true
  stillAt: 0.95,        // 减少动态效果时停在这一秒
  viewBox: "-34 -104 96 110",
  tracks: [
    { at: 0,    pose: { hipHeight: 50, lean: 8 }, ease: "inOut" },
    { at: 1.25, pose: { hipHeight: 31, lean: 34 } },
    ...
  ],
}
```

- `at` 必须递增，且不超过 `duration`。
- 关键帧上的 `ease` 管的是**从这一帧到下一帧**那一段，跟 CSS 一致。只认 `linear` / `in` / `out` / `inOut` 四个。
- `pose` 只写这个动作真正在变的量，其余落回默认值。
- `viewBox` 跟着动作走（推举要举过头顶，框得高一些），但宽高比统一保持在 0.87 上下，否则切换动作时图在页面上的占地宽度会跳。

## 加一个动作

1. 在 `clips.js` 里加一条剪辑，先写两个极端姿势（起点、终点），再看要不要中间停顿。
2. 在 `NAME_RULES` 里补一条归类正则，让它能被动作名认出来。
3. 跑 `npm test`。`motion.test.js` 会自动把新剪辑过一遍：关键帧对得上、整条时间轴不出 NaN、循环接缝不跳。
4. 打开训练页逐组屏，看它是不是真的在演那个动作。演不像就调角度，不要去改 skin。

加一个动作的正常成本是十几行数据，不应该是十几行代码。如果发现要改 `core.js`，先停下来想清楚：是这套骨架真的不够用，还是这个动作不适合用侧视线条演。

## 换一个项目

1. `motion/core.js`、`motion/player.js`、`motion/index.js` 原样复制。
2. 重写 `clips.js`：新项目的动作内容。
3. 重写皮肤：新的笔触、粗细、颜色、层级。SVG 之外（canvas、WebGL）只要实现同样的 `{ resize, paint(pose) }` 接口就能接上。
4. 视觉风格差异全部落在皮肤和 CSS token 里，**不进 clips**。这条是整套系统能不能跨项目复用的关键：一旦把风格写进动作数据，第二个项目就没法用。

## 边界

这套系统只管「有角色的动作」：人物、生物、会自己演一段的图形。

不进这套的：

- hover、focus、弹窗淡入、列表入场这类界面反馈 → 继续用 CSS transition 和 `--dur-fast` / `--dur-base` / `--ease-out`。
- 全屏氛围（树影、纸纹）→ 走 canvas，`player.js` 可以复用，但它有自己的采样逻辑。
  树影现状：`src/lib/leaf-shade.js` 按环境分三档。桌面 + 安全上下文 + WebGPU 可用时走
  `leaf-shade-webgpu.js` 的 WGSL 片元着色器（1/4 分辨率、12fps、优先低功耗适配器）；
  手机局域网 http 不是安全上下文，与桌面无 WebGPU 时一并回落 2D 精灵图（手机 1/5 分辨率、10fps）；
  系统开了减少动态效果只画一帧。两条动态路径都用 `setTimeout` 而非 rAF，
  页面不可见时连定时器一起停。档位判定在 `leaf-shade-tier.js`，跑的是 `.leaf-shade` 的 `dataset.shadeTier`。
- 过场 → 独立的一套，见下节。开练墨障（`ink-sweep.js`）仍是一次性 DOM 过场，时间写死在那里更清楚。

判断标准：**它有没有「姿势」这个概念**。有，进这套；没有，留在 CSS 里。

## 页面转场（不进动作系统）

模块切换用浏览器原生的 View Transitions API，没有自研状态机、GPU 设备和额外监听。
入口只有 `src/App.vue` 的 `go()`，样式在 `src/styles.css` 的模块切换段。

默认交叉淡出让 `::view-transition-old/new(root)` 两层同时半透明，中间帧会透出纸底发白。
按 MDN「圆形揭示」示例的官方做法，CSS 里把 `::view-transition-image-pair(root)` 的
`isolation` 设回 `auto`，并关掉 old/new 的默认 `animation` 与 `mix-blend-mode`：
旧帧保持不透明垫在下面，`go()` 在 `transition.ready` 之后用 WAAPI 对
`::view-transition-new(root)` 做 `clip-path` 圆形揭示，新帧从点击处整块盖上去。

生命周期全部交给 `ViewTransition` 本身：`updateCallbackDone` 等 DOM 换完、`ready` 挂动画、
`finished` 之后才复位滚动；页面隐藏时浏览器自动 skip；连续点击时浏览器 skip 前一个转场，
而 `swap()` 读的是最新的 `pendingKey`，最终状态落在最后一次点击。减少动态效果或浏览器
不支持 API 时直接换页，不建任何动画。没有 GPU 设备、canvas、定时器或全局监听需要清理。

交互级反馈（按钮、弹窗、Tab、区域展开）继续用 Vue 的 `<Transition>` / `<TransitionGroup>`
与 CSS transition，不在这一层。氛围层（树影、纸纹）仍走 canvas 与 `leaf-shade-*.js`。
局部交互尚未逐一接入，等这个转场稳定后再加。

## 已知限制

侧视线稿有几个解不掉的地方，遇到了直接接受，不要绕弯：

- **躺姿和趴姿现在画不了。** 卧推（`bench`）和平板支撑（`plank`）已经写好，但标了 `visible: false`，不上回归页。
  原因：侧视骨架的腿是「从髋往下长」的，整体旋转 90° 躺平后，腿会横过来和躯干叠成一个 V 字，脚也不在地面上。
  这不是调 `anchorX/anchorY` 能修的，得给骨架加「躺姿下的腿部约束」（膝屈多少、脚踩哪里）。
  **这一整类动作（卧推、上斜卧推、平板、俯卧撑、卷腹、腿举）都卡在这同一道门上。**
- **举过头顶的动作，手臂会穿过头**。头半径 7、上臂 13，无论怎么摆都会重叠，因为侧视里本来就没有深度。视觉上读成「手在头后面」是可以的。真觉得刺眼只有两条路：给手臂加一个以头为镂空的 `<mask>`，或者换成正面视角（那就不是同一套骨架了）。
- **两条腿靠 5 个单位的横向错位假装前后**。侧身站时成立，正面动作不成立。所以蹲、拉、推这些侧视动作能演，开合跳、侧平举这类**真正发生在额状面**的动作演不了。
- **手臂只有一条**。双臂同时做不同的事（交替弯举）演不了。
- **跑步演不出双腿交替**，现在靠整体起伏 + 摆臂近似。要演交替必须给骨架加第二条腿。

上面这几条不是「以后优化」，是这套骨架的边界。想越过去，得换骨架（双腿、带深度），不是改剪辑。

## 动作清单

`src/lib/motion/clips.js` 的 `CLIPS`。`visible: false` 的不上回归页。

| 分组 | 剪辑 | 状态 |
| --- | --- | --- |
| 基础模式 | `squat` 深蹲、`hinge` 髋铰链、`idle` 待机 | 可用 |
| 推 | `press` 站姿推举、`lateral-raise` 侧平举、`pushdown` 绳索下压 | 可用 |
| 推 | `bench` 卧推 | **不可用**，等躺姿约束 |
| 拉 | `row` 俯身划船、`pull-up` 引体向上、`curl` 弯举 | 可用 |
| 腿 | `split-squat` 保加利亚分腿蹲、`leg-extension` 坐姿腿屈伸 | 可用 |
| 核心有氧 | `hanging-leg-raise` 悬挂举腿、`run` 跑步 | 可用（有近似） |
| 核心有氧 | `plank` 平板支撑 | **不可用**，等躺姿约束 |

动作名归类在 `NAME_RULES`，**长正则必须在前**。踩过的坑：`悬挂举腿` 被 `引体` 抢走、`蝴蝶机夹胸` 因为没写「夹胸」直接落到 idle。
新增归类时先把真实动作名跑一遍 `kindForName` 看落点。

## 验收

新动作或新项目上线前，这六条都要过：

1. `npm test` 全绿。`tests/motion.test.js` 现在会自动查：关键帧对得上、整条时间轴不出 NaN、循环接缝不跳、**每一帧都落在 viewBox 里**、**静帧不停在起始位**、**屈肘方向朝前**。
2. 打开 `/preview/motion.html`，每个动作都看得出是在演什么。
3. 点「深墨底」看它在真实出场的 96px 上还认不认得出来。
4. 系统开「减少动态效果」时，停在一个看得出动作的静帧，不是空白也不是站直。
5. 切到别的标签页再回来，不出现跳帧、不出现加速。
6. 在 375px 宽度下小人不变形、不撑出横向滚动。

## 回归入口

`/preview/motion.html` — 动作回归页，跟 `docs/design-demo.html` 一个意思：前者看动作，后者看视觉。
已接进 `vite.config.js` 的 build input，**部署后也在**，不是 dev 专属。

- `?still=1` 强制静帧，审阅和截图时用，每次看到的是同一帧。
- `?dark=1` 换深墨底，尺寸跟逐组屏一致。
- `?at=0.35` 定格在任意相位（0–1），用来检查中间帧。
- 「慢放 0.35×」用来看关键帧之间的过渡是不是卡顿。

## 速率

两层，都能随便调：

- `createFigure(svg, { speed })` 是倍率，0.35 慢放、2 快放，任意值。
- 每条剪辑自己的 `duration` 是基准节奏。
- 想单独调某一段的快慢（下去慢、起来快），改那个关键帧的 `at` 秒数，是逐段控制，不是整体倍率。
