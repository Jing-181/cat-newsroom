这份文档定的是「小人怎么搭」，不是「动作怎么摆」。动作在 `clips.js` 里写，画法在 `skins/` 里写，两者都建立在本文的骨架上。

原则一句话：**能由几何推出来的量，不要由人逐帧调。** 杠在哪、髋升多少、脚落不落地，都应该是比例和解算的产物，不是手调的参数。

## 一、单位体系

`buildPose` 里 `ankle` 固定在原点 `y = 0`，且**足高不参与**。所以骨架里所有高度都是「踝关节以上」。

- 踝到头顶 = `stand + torso + neck + headRadius` = 50 + 29.5 + 11 + 7 = **97.5 单位**
- 解剖学上踝到头顶 = 1 − 0.039 = 0.961 身高
- 所以 **1 单位 ≈ 0.99% 身高**，整个人 ≈ 101 单位

换算到真人：身高 175cm 时 1 单位 ≈ 1.73cm，165cm 时 ≈ 1.64cm。

这个尺度本身是对的（97.5 单位 = 0.961 身高，误差 0.1%），所以不需要整体缩放，只需要**重新分配**。

## 二、分段比例

以 Drillis & Contini (1966) 的闭合链为准。选它而不是取平均的理由：它的分段长与 Dempster 的刚体模型自洽，是六十年的通用基准，且能保住 `stand = 50` 与总高不变。

| 字段 | 值 | 身高占比 | 依据 |
|---|---|---|---|
| `stand` | 50 | 0.491 | 大转子 0.530 − 外踝 0.039 |
| `thigh` | 25 | 0.245 | 0.530 − 0.285 |
| `shin` | 25 | 0.246 | 0.285 − 0.039 |
| `torso` | 29.5 | 0.288 | 0.818 − 0.530 |
| `upperArm` | 19 | 0.188 | 0.818 − 0.630 |
| `forearm` | 15 | 0.145 | 0.630 − 0.485 |
| `neck` | 11 | 0.107 | 肩峰 → 头心 |
| `headRadius` | 7 | — | 头心到头顶，总高闭合用 |

验算这条链，每一环都对得上真实人体（在踝以上）：

```
髋 50 → 肩 79.5（真实 79.5）→ 腕 45.5（真实 45.5）
      → 头心 90.5（真实 tragion 90.4）→ 头顶 97.5（真实 97.5）
```

**腕落在髋下方 4.5 单位** —— 这是解剖学中立姿势的判据，也是这套骨架是否可信的验收点。

### 为什么要换

上一版是 `thigh 26 / shin 26 / torso 32 / upperArm 13 / forearm 13 / neck 9`，三个后果可算：

1. **站直从来不是直的。** `thigh + shin = 52` 但 `stand = 50`，IK 被夹到 50，站直帧的膝屈恒为 **31.9°**，膝盖向面朝方向前移 **7.1 单位**。所有「站直」都是微蹲加膝前顶。
2. **臂短了 8 单位。** 26 vs 真实 34。腕落在髋**上方** 6 单位，而真实应在髋**下** 4.5，差了 10.5 单位。硬拉杠停髋上、卧推行程少 23%、划船的杠够不到腹部，全是这一条，不是调参能解决的。
3. 躯干长了 2.5 单位，腿短了 2 单位。

换成现值后实测：站立膝屈 **2.3°**、膝盖前移 **0.5**、臂长 **34**、腕相对髋 **+4.5（在下）**、头顶高 **97.5**（总高保住）。

### 来源分歧，没有取平均

| 量 | D&C 1966 | ANSUR II 实测 | 取值 |
|---|---|---|---|
| 髋（大转子） | 0.530 | 0.512 | **0.530** |
| 膝 | 0.285（维度未定义） | 0.278 髌骨中 / 0.280 外上髁 | **0.285**（建议用外上髁 0.280） |

髋这一项差 3.1cm，是唯一真要紧的分歧，直接决定腿长和躯干怎么分账。采信 D&C 的代价是躯干略短、腿略长。

如果改采 ANSUR 的髋，备选整套是 `stand 47 / thigh 23.5 / shin 23.5 / torso 32.5 / upperArm 19.5 / forearm 15.5`。**两版唯一一致的是手臂必须在 34–35，腕必须在髋下 2–5 单位**，这条不分来源，是硬约束。

肩/肘/腕/指尖这四点两个来源吻合到 0.5% 以内（0.820 vs 0.818、0.629 vs 0.630、0.483 vs 0.485、0.373 vs 0.377），说明 D&C 的转录没出错，分歧只在髋和膝这种「骨突摸不准」的点上。

**可信程度**：D&C 的数值是二手转录（Fromuth & Parkinson 2008 的 Figure 1 复刻图），原始报告未取得。ANSUR II 数值取自第三方查看器，声明与原报告一致。头高 0.130 是 Kollmann 古典规范（经 Drillis 等 1964 转述），不是实测。

## 三、关节中心与自由度

每个关节都是一个点加一个角度，角度定义统一：**0 为解剖中立，正方向为运动方向**。

| 关节 | 旋转中心 | 参数 | 0 的定义 | 生理范围 |
|---|---|---|---|---|
| 踝 | 外踝 | — | 固定原点 | 背屈 20° / 跖屈 50° |
| 膝 | 股骨外上髁 | `kneeFlex` / `freeKnee` | 完全伸直 | 0–140° |
| 髋 | 大转子 | `hipHeight` + `hipShift` | 直立站姿 | 屈 120° / 伸 20° |
| 躯干 | 髋→肩连线 | `lean` | 竖直 | — |
| 肩 | 肩峰 | `armSwing`（+ 反解） | 自然下垂 | 屈 180° |
| 肘 | 肱骨外上髁 | `elbow` | 直臂 | 0–145° |

### 两条解算路径，用哪条由约束决定

- **腿用 IK**：踝被地面钉住时（站立、蹲、弓步），给定踝点和两段骨长反解膝盖。距离超出身高时靠 `clamp(cos)` 落地成「腿伸直」，不预先减余量（减了会让小腿量出来比骨长多 0.01）。
- **手臂用正向解算**：手臂自由摆动时（弯举、侧平举）直接给角度。
- **手臂用反解**：手被器械钉住时（硬拉、卧推），由「杠在哪」反推上臂角和屈肘角。同一目标点两解，`armFold` 选折叠方向。

### 身体位移由几何推出来

`gripY` 给定后，身体整体平移让手正好落在杠上，迭代 4 次收敛（`err = pose.hand.y + gripY`）。引体向上的「髋升多少」不需要人猜，是屈肘角的函数。

同理 `barX` / `barHeight` 给定后，手臂反解，杠走直线而身体跟上去。**器械高度不是独立常量，必须由臂长反推**：

- 站立时肩在 79.5，臂 34，掌就在 **45.5**。硬拉锁定的 `barHeight` 只能是这个数，写 58 就是「屈肘撞锁定」。
- 卧推锁定位的上限同理是「肩 + 臂」，旧值 51 恰好是旧臂 26 的天花板——那不是设计，是撞墙。

## 四、体位的支撑约束

不同体位的「地面」不是同一个东西，这是骨架最容易出错的地方。

| 体位 | 支撑 | 约束 | 实现 |
|---|---|---|---|
| 站立 | 双足 | 踝钉在地面线 | IK，`hipHeight` 决定膝屈 |
| 下蹲 | 双足 | 踝钉死，髋下沉 | 同上，`hipHeight` 变化 |
| 俯身 | 双足 | 髋后移、膝微屈、踝不动 | `hipShift` + `lean` |
| 悬挂 | 双手 | **握点钉死，身体动** | `gripY` 锚定，腿改正解 `freeLegs` |
| 躺姿 | 背、臀、足 | 躯干水平，腿仍从髋往地面踩 | `lean 90`，不整体旋转 |
| 腾空（跑） | 无 | 双脚都不接地 | `freeLegs` + `footFlat` |

**躺姿的关键**：不要用 `rootTilt 90` 把整个人转倒。转了之后腿会跟着躯干横过来，和躯干叠成一个 V 字。正确做法是只把躯干放平，腿继续从髋往地面方向解。

**腾空的关键**：跑步有 flight phase，脚本来就不接地。用 `freeLegs` 让两条腿都走角度正解，两腿反相，大腿摆幅共 50°（前 32° / 后 −18°），膝屈 18° 到 105°，手臂与同侧腿反相、肘角 78–88°。脚用 `footFlat`（世界水平），因为落地那一刻是脚跟先着地、脚尖背屈朝上，让脚尖顺着小腿往下戳是错的。

## 五、肌肉走向（线稿的线条语义）

线稿不画写实肌肉，但要保证「哪一笔代表哪块」是稳定的，否则小尺寸下所有线都退化成纹理。

**外轮廓笔**（最粗）：躯干前缘、大腿、上臂。这三处定义了体积的边界。

**肌肉走向笔**（中粗）：沿肌纤维方向，不是沿骨骼方向。

| 部位 | 线 | 走向 |
|---|---|---|
| 胸 | 胸下缘 | 从胸骨向腋窝，略上扬 |
| 腹 | 腹直肌外缘 | 竖直，随躯干倾角 |
| 背 | 背阔肌下缘 | 从腋后向腰，斜向内下 |
| 肩 | 三角肌前束分界 | 沿上臂近端，与上臂平行 |
| 上臂 | 肱二头肌峰 | 沿上臂前缘，中部隆起 |
| 前臂 | 桡侧肌群 | 沿前臂，靠近肘端粗、腕端细 |
| 大腿 | 股四头肌分界 | 沿大腿前缘，与股骨平行 |
| 小腿 | 腓肠肌内侧头 | 沿小腿后缘，膝下 1/3 处最厚 |

**关节处的连续性**：骨端各收 0.4 单位再连接，避免两条粗线在关节处叠成一个黑点。关节圆点只在 regular 及以上尺寸给，compact 档归零。

**远侧肢体**：靠线宽（0.7 倍）、透明度（0.45）、横向错位（1.2 单位）表达纵深。三者同时用会过重，小尺寸下只留透明度。

## 六、视角：每个动作的最好展示角度

判据一句话：**视角跟着运动平面走，不跟着动作品类走。**

动作发生在哪个平面，就从那个平面看。写错不会报错，只会「看着在动，但该动的关节没动」。

所以视角是数据：每条剪辑自己声明 `view`，解算器读它决定用哪套骨架。

### 两套骨架

| | `view: "side"`（矢状面） | `view: "front"`（额状面） |
|---|---|---|
| 看得到 | 前屈、后伸、上下、行进 | 外展、横向开度、左右对称 |
| 看不到 | 外展、左右差 | 前后位移、躯干前倾 |
| 参数 | `armSwing` / `lean` / `freeLegs` / `gripY` | `armAbduct` / `stance` / `foreshorten` |
| 深浅 | 远侧肢体要错位 + 降低透明度 | 两侧等距，不存在远侧 |

两套参数不能混用。正面解算器不读 `armSwing`，写了也不报错，只是默默失效。测试里有一条专门拦这个。

### 逐条归档

| 动作 | 视角 | 依据 |
|---|---|---|
| 深踝 / 髋铰链 / 分腿蹲 / 腿屈伸 | 侧 | 屈伸全在矢状面 |
| 硬拉 / 划船 / 弯举 / 绳索下压 | 侧 | 同上 |
| 卧推 | 侧 | 见下文的否定结论 |
| 站姿推举 | 侧 | 矢状面；侧视才能看到头部避让 |
| 引体向上 / 悬挂举腿 | 侧 | 主要看身体沿杠上下，不是看两手张多宽 |
| 平板支撑 / 跑步 | 侧 | 同上 |
| 侧平举 / 夹胸 / 反向蝴蝶 | **正面** | 额状面外展。侧视里手臂「抬到肩高」在矢状面投影里本来就不该离开身体轮廓 |

最后一行涵盖了一个归类的整个桶：`lateral-raise` 同时服务侧平举、夹胸、反向蝴蝶、俯身飞鸟、面拉，这四个都是额状面动作，所以改一次正面全受益。

### 卧推试过正面，判定失败

试过的做法：镜头放在脚那头，躯干沿视线压扁（`foreshorten 0.3`），双臂向上推，横杠跨在两手之间。

结果是：身体压短、头在后端缩成一个点，整张图读起来是「一个人站着往上推」而不是「躺着推」。

根因：侧卧的识别度不靠「身体形状」，靠「地平线参照」——人位于地面之上、身体水平、腿往下踩。轴向投影把这些全拿掉了。

结论：卧推留在侧视。它现在有训练椅和杠铃两件道具撑着，已经读得出来。如果以后真要做对，得引入透视（近大远小 + 地面矩形），不是调参数能解决的。

### 正面骨架的画法

形的语言是**单线**，正面也不例外。

躯干就是一条竖线，不加梯形、不加厚度。但四肢接在 ±10 两侧、脊柱在中轴，
所以必须补两条横线：**肩线**与**髖线**。少了它们，身体就是断的——
胳膊腿浮在离脊柱十几个单位的地方。两条横线本身也是线，不是面，风格不变。

器械在正面要按投影画：哑铃的轴指向镜头，投影就是一个点，
画成横杆会被读成杠铃端面，而且左右各一根，看着像两根杠。

### 形本身的基准：`preview/body.html`

三块板子：侧视 / 正视 / 对照，同一比例、同一 viewBox。
用来回答一个间题：**这两个方向指的是不是同一副骨头？**
判据是身高、肩高、髖高、膝高、踝高五条线要对得上。对不上就是某一侧的解算错了。

## 七、器械与支撑物

器械不是装饰。一个动作的识别度很大一块在「手被什么东西牵着」和「身体被什么东西托着」。

两种层次，不能混：

- **手具**（`prop.kind`）：杠铃、引体杆、哑铃、绳索。它跟着手走，所以画在手所在的层。
- **支撑物**（`prop.setup`）：训练椅、坐姿凳。它承托身体，所以永远画在身后一层，不能压在人身上。

卧推两个都要（练凳 + 杠铃），所以 `prop` 必须能同时表达两件东西：
`{ kind: "barbell", at: "hands", setup: "bench" }`。只有一件时（坐姿腿屈伸的椅子）直接当 `kind` 用。

**线条稿支持**：barbell / bar / dumbbell / cable / bench / seat。
体积线和 3D 目前只支持前三种，遇到不认识的会**不画**而不是当成杠铃凑一个——画错比不画错得多。

一个具体的教训：新增的图形节点如果没在 `applyStyle()` 里设 `stroke-width`，路径数据全对、DOM 里搜得到，屏幕上什么都不出。线宽不是默认值，是每个节点自己领的。

## 八、能力边界：现在还画不了什么

诚实列出，避免拿错的投影假装画对了。

### 运动平面

**现在有两套：矢状面（侧）和额状面（正）。**

侧面看得到：蹲、髋铰链、划船、弯举、推举、引体、跑、悬挂举腿。
正面看得到：侧平举、夹胸、开合跳这类向两侧展开的动作。

**没有的是四分之三视角**。真实的 3/4 视角需要一套三维骨架加透视投影，两套平面骨架拼不出来。
不拿平面的假斜视去冒充 3/4，那和「侧视冒充正面」是同一类错。

**两个皮肤暂停**：体积线和 3D 暂时不做了（2026-11-07 定）。先把线条稿的形定死，
三条并排反而没一条能看准。两个皮肤的文件都还在，只是从对照页里撤了。
而且它们只认侧面那套字段，遇到正面剪辑会缺一条胳膊一条腿。

### 卧推的固有冲突

侧视里卧推有两个诉求不能同时满足：

- 杠落到胸口 → 手到肩的距离只有 4.7 单位，肘要折到 172°
- 肘角 90° → 手到肩 24 单位，杠就悬在胸口上方 24 单位

真实卧推靠肘向体侧外展解决这个矛盾，而外展在纯侧视里看不见。现在选的是「杠贴胸 + 行程 29.5 单位」，代价是底位肘折得极深。要真读对，得用正面或三/四视角，那是新骨架的活。

### 肩胛节律缺失

肩屈曲 180° 里盂肱关节只贡献约 120°，剩下 60° 来自肩胛。两段臂没有肩胛，所以**过头推举的末端会系统性低估 5–7%**。要么给 `barHeight` 加上限，要么允许胸椎后伸补偿。这条是已知偏差，不是 bug。

### 手长没建模

握杠点在腕下方约 1–2 单位。逐帧对位时这个偏移会被误读成臂长误差。足长画 14 单位 vs 真实 0.154 身高（短约 1.5 单位）。

## 九、换比例要连带改什么

比例不是孤立常量，改它会牵动所有「按旧臂长定的数」。这份清单是给下一次改动用的：

1. `barHeight` / `barX`（硬拉、卧推）——必须由新臂长反推
2. `gripY`（引体、悬挂举腿）——杠高必须让人真离地，臂长了 8 单位，杠也要相应升高
3. `freeThigh` / `freeKnee`（跑步、悬挂类）——腿短了 1 单位，摆幅不变但位置略变
4. 各剪辑的 `viewBox`——长骨变短会让某些帧的末端探出框
5. `hipHeight` 的绝对值——`stand` 没变，但蹲深的相对值要复核
