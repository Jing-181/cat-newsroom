# 猫咪生活报产品基线（2026-09）

> 核对日期：2026-09-19。来源：用户使用反馈、仓库代码、现有规划文档与测试结果。当前自动测试共 37 项。

## 结论

项目已经是一个可用的个人生活工作台，下一阶段的主要问题是核心路径没有收敛，而不是功能数量不足。当前真实使用信号显示：运动是高频入口；番茄钟有即时工具价值；Todo、习惯和猫咪日记应保持轻量；AI 周报应负责解释已有数据。

产品定位暂定为：

> **猫咪生活报：记录正在发生的生活，也留下值得回看的生活。**

信息架构逐步围绕“今日”和“回顾”组织。运动是核心能力，其他模块作为低频资料或辅助工具存在。

## 已确认的实现事实

- AI 六天训练建议已有 `js/workout-ui.js` 入口，归为已有能力，暂缓扩展。
- 新增动作在 `js/workout.js` 中默认建立一组；新增组在 `js/workout-ui.js` 中默认标记完成。逐组确认是后续交互决策，不是本批样式任务。
- 上次数据由 `previousPerformance()` 查找最近训练中最后一个完成组，并带入重量、次数等字段，不复制整次训练。
- 训练 Session 使用现有 `workout_session` 模型和原子同步，不新增服务端接口或数据库迁移。
- `npm run check` 当前通过，共 31 项测试（含共享样式、周报触发边界和训练计划模型检查）；`package.json` 没有 `build` 脚本，开发规范应以现有检查命令为准。

## 产品决策

### P0：设计基准与核心入口

1. 共享主题、通用组件和设计演示页先于新功能。
2. 首页下一批改为“今日头版”：运动入口和真实训练状态优先，Todo、番茄和生活记录为辅助信息。
3. 运动下一批优化记录效率，先测量真实训练路径的操作次数，再决定交互改动。

### P1：轻量记录与回顾

1. Todo 采用 Capture First，先保证三秒内输入并回车保存。
2. 习惯支持简单完成和补记，不扩展勋章、排行和连续打卡激励。
3. 猫咪日记支持低成本偶发记录，不要求每日使用。
4. 每日头版、历史和 AI 周报形成“记录 → 回顾”闭环。

### 暂不排期

复杂 Todo、生活评分、AI 聊天、社交、排行榜、复杂训练计划和大量第三方集成。

## 本轮问题记录

运动动作弹窗闪关的根因不是训练动作接口，而是两个 workbench 在页面初始化完成全量同步后，无条件调用 `maybeGenerateWeeklyReport(false)`。周报函数在请求前后执行全局 `render()`，运动页因此重新挂载 `WorkoutUI` 并销毁已打开的动作选择弹窗。

已完成的处理：

- 初始化和登录恢复不再自动调用周报 Edge Function。
- 周报请求只由用户点击周报按钮触发，且只更新 `#weekly-report-slot`。
- 请求带序号保护，旧请求不能覆盖新状态；生成中最多轮询 4 次。
- 六天计划使用 `js/workout-plan.js` 统一规范化和保存，记录生成上下文，并在覆盖旧计划前确认。
- 本地备份使用 `js/data-backup.js` 生成版本化 JSON；导入只覆盖当前浏览器本地数据，需确认后执行，不自动写云端。

验证边界：40 项自动测试及差异格式检查已通过；修改后的运动动作弹窗移动端真实点击回归已完成，桌面、多视口、键盘和隔离数据回归仍需收口。

## 新一轮结构问题

- 首页尚未完成“今日头版”重排；前几轮主要处理共享样式、同步、备份和运动弹窗，因此首页可见变化有限。
- 两个 workbench 仍分别包含大段页面状态、模板和 CSS；后续使用 Vue 3 + Vite 逐模块迁移，保留旧入口作为回退，不一次性重写。
- 生活报函数已部署且 `AIXLUV_API_KEY` 已配置，但此前请求无超时且客户端只能看到笼统失败；本轮加入共享 API 请求层、客户端 50 秒超时、模型查询 15 秒超时、AI 生成 60 秒超时和服务端错误透传。当前页面为 `file://` 且未提供正式账号请求证据，具体上游错误仍需正式账号实测。
- 运动计划主场景已确认：训练前选择计划，训练中逐组记录。现有功能只是生成并查看建议，后续拆分计划建议、计划实例和 `workout_session`。
