# 前端架构迁移与核心体验计划

核对日期：2026-09-19。当前线上入口仍是两个静态 workbench；本计划将 Vue 3 + Vite 作为下一阶段实现底座，迁移完成前保留旧入口和现有本地数据键。

## 现状与问题

- `workbench-desktop.html` 约 1800 行，`workbench-mobile.html` 约 1600 行，页面结构、业务状态、请求回调和样式混在入口文件中。
- 运动模块已经有共享模型和 UI 控制器，但 Todo、习惯、阅读、记账、日记、洞察仍主要由两个 HTML 各自渲染。
- `supabase-sync.js` 同时承担认证、记录同步、Realtime、图片上传、周报和训练计划请求；本轮先抽出通用 JSON 请求客户端，后续按领域继续拆分。
- 首页信息密度高，但没有明确的今日主线；运动入口和真实训练状态没有稳定占据第一优先级。
- AI 周报函数和训练计划函数依赖外部模型服务；原请求没有超时，失败原因不够直接，生成中状态容易让用户误以为页面仍在工作。
- 六天计划当前是“生成并查看建议”，尚未成为“训练前选择计划、训练中逐组记录”的工作流。

## 迁移原则

1. Vue 组件只负责界面状态和组合；数据键、`workout_session` 模型和同步协议保持兼容。
2. 服务层按领域拆分：`auth`、`records`、`sync`、`weekly-report`、`workout-plan`、`backup`；组件不直接拼接 Supabase URL。
3. 样式按 token、基础组件、模块组件和布局覆盖分层；桌面侧栏、移动底栏和抽屉保留端差异。
4. 每迁移一个模块，必须同时保留旧入口回退、补测试、更新设计演示页，并比较同一数据下的操作次数。
5. 先迁移一个可独立验收的模块，再扩大范围；不进行一次性全量重写。

## 迁移批次

### A0：稳定性和诊断（当前）

- 周报/训练计划请求共用超时和错误解析；函数端限制模型列表和生成请求时长。
- 全量同步保护 outbox，避免本地待上传数据被旧云端快照覆盖。
- 记录真实失败原因：未登录、函数未部署、周报表/RLS、AI Secret、模型服务、超时分别显示。

### A1：Vue 工具链和壳层

- 增加 Vue 3、Vite、TypeScript 和测试脚本，但不切换线上入口。
- 先实现 `AppShell`、桌面侧栏、移动底栏、抽屉、同步状态和路由视图占位。
- 通过同一 `services/records` 读取现有 `cat-newsroom-data-v2`，验证旧数据可展示。

### A2：服务层拆分

- 将认证、记录 CRUD、Realtime、备份和两个 AI 请求从 `supabase-sync.js` 拆到领域服务。
- 统一请求超时、取消、错误码和重试策略；全量同步只在初始化/手动同步发生。
- 增加网络断开、恢复、重复提交、多标签页和 Realtime 测试矩阵。

### A3：今日头版

- 首页第一屏只保留真实训练状态、今日待办、专注和最近生活记录的必要摘要。
- 没有真实数据时显示空状态，不生成虚构安排。
- 运动入口可以直接开始/继续草稿；其他模块保持辅助信息。

### A4：运动计划与记录工作流

- 主场景确定为“训练前选择计划，训练中逐组记录”。
- 计划实体包含计划版本、训练日、动作、目标组次/次数、完成状态和来源；选择计划后生成可编辑训练草稿。
- 训练中记录沿用 `workout_session`，支持逐组完成、临时调整、暂停和结束保存；计划建议和实际记录分开存储。
- 计划生成失败时保留旧计划和当前草稿，不清空页面；重新生成必须确认覆盖。

### A5：组件化模块迁移

按风险和频率排序：运动 → Todo → 习惯 → 洞察/周报 → 阅读/记账/日记/收藏。每个模块完成后再删除对应旧模板，保留一段时间的回退开关。

### A6：样式与入口收口

- 迁移公共 token、按钮、表单、弹窗、空状态和状态提示到 Vue 组件。
- 双端只保留布局覆盖，删除重复页面 CSS。
- 视觉回归覆盖 375、390、430、820、1280、1440px，补截图和键盘焦点检查。

## 完成定义

- 新入口能在隔离数据下完成首页、运动开始/记录/保存、周报重试、备份恢复和端切换。
- 旧入口和新入口读取同一数据键，互相切换不丢数据。
- `npm run check`、Vue 构建和组件测试通过；网络错误、取消请求和空数据均有可见状态。
