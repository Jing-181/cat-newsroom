# 猫咪生活报设计系统

> 视觉基准：复古报刊 × 个人生活 × 温暖 × 克制 × 一点猫咪趣味。规范描述规则，`design-demo.html` 展示实际效果。

## 使用规则

- 新组件先使用共享 CSS 变量和组件类，再添加页面或模块专属样式。
- 不在 workbench HTML 中新增主题变量；页面只保留布局和业务状态。
- 修改公共组件时同步更新本页与 `docs/design-demo.html`。
- 两端共用颜色、字体、状态和语义；桌面与移动只在布局尺寸、导航形态和可用空间上覆盖。
- 新颜色、圆角和阴影必须先说明用途，避免为单个页面创建相似 token。

## 字体、间距与形状

- 报刊标题和内容使用 `--font`：Georgia、宋体优先。
- 控件标签、数字和密集信息使用 `--font-sans`。
- 间距基线：4、8、12、16、24、32、48px；优先使用 8 的倍数组织区块。
- 圆角只用四个 token，不再写一次性字面量：`--radius-control`（10px，输入、步进、图标底板）、`--radius-tile`（12px，按钮、标签、小卡、记录卡）、`--radius-card`（12px，模块卡与瓷砖，与 tile 同值，暂不分化）、`--radius-sheet`（20px，通栏、抽屉与弹窗）、`--radius-pill`（999px，胶囊）。小于 22px 的方框（勾选框、邮票格）允许 4–8px 的小圆角。
- 全站默认 `corner-shape: squircle`，圆角按超椭圆渲染；不支持该属性的浏览器自动回退为普通圆角。需要保持正圆的元素（圆点、圆形标记、圆形关闭按钮）显式设回 `round`。
- 阴影：普通卡片 `--shadow-card`；hover 用 `--shadow-hover`；弹窗、浮层和 Toast 用 `--shadow-overlay`。
- 动效：统一用 `--dur-fast`（.15s）/ `--dur-base`（.22s）与 `--ease-out`；hover 只用 fast，`prefers-reduced-motion: reduce` 时全局关闭。这两组 token 只负责界面反馈（hover、focus、弹窗、列表入场）。有角色的动作（训练页小人这类会自己演一段的图形）不走 CSS，走 `src/lib/motion/`，规则见 `docs/motion-system.md`。
- 浮层分工：弹窗、抽屉、Toast 的进入用 `--dur-base`，遮罩淡出、Tab / 折叠箭头、按钮 hover 用 `--dur-fast`。底部 Tab 的 active 变色也走 `--dur-fast`，不再瞬时跳。别在界面反馈里再写一次性时长或另一条缓动曲线。
- 字重：正文 400/500，标签与标题 700，只有超大数字和报刊刊头用 800。不再新增 750 这类非标准字重。

## 组件与状态

共享组件类位于 `css/components.css`：

- `.shared-btn`：默认、`.primary`、`.ghost`、`.danger`、禁用和键盘焦点。
- `.shared-field`：输入、选择、文本域及焦点状态。
- `.shared-card`：重复数据项和示例面板。
- `.shared-empty`：无数据状态，必须同时提供原因和下一步操作。
- `.shared-modal`：弹窗表面；实际确认逻辑继续使用 `js/app-dialog.js`。
- `.shared-status`：成功、警告和错误状态。

交互状态必须可辨识：hover 只增强边框或背景（不做位移抬升），active 有轻微位移，focus 使用 `--accent` 外描边，disabled 降低透明度且不可点击，loading 保留布局尺寸，error 使用 `--danger` 和可读文案。

模块页目前仍沿用遗留的 `.btn` / 原生 `input` / `.rec` 等类，`.shared-*` 是目标形态；两者的视觉由同一套 token 保证一致，迁移进度见 `docs/design-review-2026-10.md`。

## 双端规则

- 桌面：固定侧栏，内容区保持可扫描的多列布局；`--sidebar-w`、`--drawer-hover` 和 `--drawer-active` 属于桌面布局覆盖。
- 移动：单列内容，底部导航占用 `--nav-h`；抽屉和弹窗可以使用底部 sheet，并使用共享默认抽屉状态。
- 375、390、430px 宽度下不得出现横向滚动；数字、按钮和训练组需要稳定尺寸。
- 820px 是自动端模式边界；触控设备在 1024px 以下优先移动布局。821–1099px 属于桌面外壳但宽度不够，多列网格降为两列（见 `src/responsive.css` 末尾的中间断点）。
- `prefers-reduced-motion: reduce` 时取消非必要位移和动画。

## 训练状态栏移动布局

在≤820px（及≤1024px粗指针），`focus-heading` 将标题放左列，动作序号、组/段操作与停留计时放右列。标题使用自然高度，长标题换行，不与右列重叠。隐藏上/下动作按钮，保留左右滑动；组操作入口至少44px高，以省略号提示更多操作。隐藏与当前组数重复的进度点，桌面仍保留原导航与进度点布局。短视口/软键盘时训练容器允许纵向滚动，表单行不压缩。仅顶部元信息增加包装，示范、主操作区仍是原训练容器的直属flex子项；safe-area和viewport滚动契约保留，导航规则见下方「模块布局」。

逐组记录的 SVG 动作示范高度随视口在128–176px之间调整，示范区保留同等最小高度；短屏允许滚动到记录按钮，避免图形与下方提示重叠。

## 随记与事项编辑

随记列表多图使用紧凑缩略图（最大96×80px），点击查看原图；编辑器预览高72px，最多9张，旧单图记录仍可编辑。缩略图仅裁切展示，不修改原图。手机内容输入使用16px字号，内容区顶部对齐；沿用可见视口高度、独立正文滚动和底部保存区，不新增外层滚动。照片移除按钮移动端至少44px高。

事项分组仅拖动手柄接管触屏手势，其他区域照常滚动；支持方向键排序，搜索期间禁用排序。顺序按账号保存在当前浏览器，不跨设备同步。

## 助手编辑部

首页以一行三人署名栏展示 Hanako、源、悠，模块助手入口归入手机顶栏与桌面侧栏，不在正文顶部单占一行。原画保留纸色，字体、边框、圆角与按钮反馈复用共享 token；不另建角色主题。三人共享上下分隔线，手机以 44px 头像加姓名展示，短说明留在介绍卡。介绍卡使用原生 dialog，支持键盘焦点、Escape 关闭和模块快捷入口。

表情精灵交由 `motion/player.js` 播放，每次 2.4 秒后静止，离屏与后台暂停；减少动态时展示静帧并隐藏重播按钮。素材出处与候选状态见 `src/assets/assistants/README.md`；这是角色介绍与导航，不代表实时 AI 在线状态。

## 模块布局（2.23.2）

普通手机页面保留紧凑品牌顶栏和底部导航，正文直接从模块标题开始。助手动图在顶栏使用44px按钮；桌面放侧栏。运动图鉴并入运动标题操作区，窄屏标题与操作分两排，放弃/退出编辑靠右；底部训练操作条位于导航上沿，适用至820px。

逐组记录已有训练标题，手机收起品牌顶栏，保留底部导航及训练内的图鉴、总览。移除旧的手动全屏开关，不再读取旧全屏偏好。训练滚动区域高度扣除底部导航与安全区，短屏及软键盘下不把主操作藏在导航后面。未新增主题token。

## 首页与手机工具栏（2.23.3）

随手记的输入和保存合并成一个书写区，记一笔/加事项使用分段控件；图文日记、运动、收藏、时间线入口收进「更多记录方式」，展开不清空草稿。专注卡使用大号等宽数字、浅色开始按钮与弱化的重置入口，继续使用现有计时器。

≤820px 时，收藏、阅读、打卡、记账、随记统一搜索和新建同行，输入字号16px、主要按钮至少44px高；通用记录页省去重复日期，摘要卡适度收紧。事项搜索和「＋ 分组」同行，分组表单默认收起，主动展开后聚焦输入；收起保留草稿，创建后清空搜索并聚焦新组的事项输入。排序说明按需展开。桌面分组表单仍直接可用。

手机记录卡把工具按钮留在顶部，不再为整段正文预留右侧工具列；收藏摘要按正文最多两行截断，避免长文横向裁切。全部沿用现有主题token。

## 回归入口

打开 `docs/design-demo.html` 检查颜色、字体、按钮、表单、卡片、弹窗、状态和移动布局。它使用与两个 workbench 相同的共享 CSS，并使用固定样例数据，不读写个人记录。

动作动画是另一条线，入口是 dev server 下的 `/preview/motion.html`（`?still=1` 静帧、`?dark=1` 深墨底），规则见 `docs/motion-system.md`。
